The system I'd want to talk about

A job scheduler for many tenants at once

Background work on the platform — points accrual, tier recalculation, statement generation — ran on a polling runner that woke on a fixed tick and scanned every organisation's job table. Cost scaled with the number of tenants rather than the amount of work, and one busy tenant could hold up everyone else. I replaced it with a dispatcher, and moved the traffic across without taking the platform down.

Dispatch pipeline
completed retry dead letter
Correctness

One dispatcher, always

Replicas stand by; a single elected leader claims work. A job is never picked up twice, and if the leader dies another takes over without anyone being paged.

Ordering

Priority that ages

Jobs enter with a priority and gain weight the longer they wait. Urgent work still goes first, but nothing sits at the back of the queue forever.

Isolation

Fair share across tenants

Dispatch rotates between organisations, so a tenant submitting ten thousand jobs cannot crowd out the tenant submitting three.

Backpressure

Four levels of limits

Global, per-organisation, per-job-type and per-worker. Each guards a different failure: the database, the noisy neighbour, the slow third-party integration, the box itself.

Failure

Nothing fails quietly

Retries run inside a bounded budget; whatever exhausts it lands in a dead-letter queue where it stays visible and replayable instead of disappearing.

Migration

Both runners, side by side

A bridge kept the legacy runner and the new scheduler consistent while traffic moved across, so the cutover shipped with no downtime. 36 unit tests went with it.

Intelliest Technology · client: mjunction

B2B Channel Loyalty & Rewards Platform

Current

A multi-tenant, configuration-driven loyalty programme for business channel partners, built as 20+ NestJS microservices communicating over RabbitMQ with Next.js frontends. It covers member onboarding, purchase and lead registration, points accrual, tier management, catalogue redemption, point-to-cash payouts and reporting — every tenant running its own rules on one shared codebase.

What I built
  • The multi-organisation job scheduler. Replaced a legacy polling runner with a leader-elected dispatcher: priority with aging, fair-share dispatch across tenants, four levels of concurrency limits, retry and dead-letter handling, and a legacy bridge that made the cutover zero-downtime. Shipped with 36 unit tests.
  • Point-to-cash redemption hardening. Moved point reversal inside the status-change transaction and added idempotent guards, so a retried request can no longer double-refund. Every redemption now carries a complete, auditable status history.
  • The authentication and profile service. JWT sessions, OTP issued against short-lived purpose tokens, Joi validation and i18n — including OTP-verified mobile-number change and event-driven tier assignment on self-registration.
  • The admin operations panel. Redemption approvals, sale-data verification and live order-status monitoring, in Next.js with Ant Design and Redux Toolkit.
Role

Full-stack engineer. Owner of job scheduling, authentication and the payout path.

Arodek Technology Consulting · 2022–24

Gurukul — Training Tracker Portal

Hierarchical access

A training-progress portal for a multi-level organisation, where state heads, regional heads and centre staff all need the same report scoped to their own slice of the hierarchy — and must not see anyone else's.

What I built
  • REST APIs on Node.js and Oracle DB using an MCR architecture, serving training and progress data to every level of the org tree.
  • The hierarchical access model, where a user's position in the tree determines the rows they can read — a state head sees their regions, a regional head only their own centres.
  • Role-based React dashboards that render the same progress view at whichever level the viewer sits, so one interface serves the whole hierarchy.
  • Firebase integration for real-time session alerts and progress notifications, which is what actually pulled trainers back into the portal.
Role

Full-stack developer — APIs, access model and dashboards.

The interesting part

Expressing an arbitrary-depth org hierarchy as query scope, without a permission check in every endpoint.
